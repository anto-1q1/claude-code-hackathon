Discovery

What we actually found.

Five blockers. Two of them invisible until we dug in.

🔌

Hardcoded IP Blocker

Database connection hardcoded to 10.0.1.82. RDS failover would have been invisible to the app.

🔐

Credentials in plaintext 7 Years

DB password in source code since 2017. No rotation ever. Git history scrub required.

📁

NFS dependency

Both web app and batch write to a shared network drive. Doesn't exist in AWS.

💾

Sessions on local disk

/tmp/flask_sessions/ — Fargate autoscaling would log out every user.

🕵️

Hidden dependency — Unknown to the dev team Surprise

The batch job called webapp/api/warm-cache via hardcoded IP 5 minutes before running. Migrating workloads independently would have caused silent failures at 02:00.

Architecture Decisions

8 ADRs. Every choice documented.

  • ADR-0001
    DNS over hardcoded IPs
    Replaced 10.0.1.82 with DB_HOST env var — RDS failover now transparent to the app
    Accepted
  • ADR-0002
    Separate S3 buckets per workload
    Different retention policies (90 days vs 7 years) require isolation — simpler IAM, reduced risk
    Accepted
  • ADR-0003
    AWS Secrets Manager + git history scrub
    Credentials in plaintext for 7 years — auto-rotation + CloudWatch log redaction
    Accepted
  • ADR-0004
    Session state → ElastiCache Redis
    /tmp/flask_sessions breaks Fargate autoscaling — Redis makes the app fully stateless
    Accepted
  • ADR-0005
    Decouple batch/webapp via EventBridge
    Hidden cron dependency discovered — extracted to standalone warm-up task
    Accepted
  • ADR-0006
    ECS Fargate + AWS Batch
    Lambda rejected (15-min limit); EKS overkill for single service; Batch saves ~22h idle EC2/day
    Accepted
  • ADR-0007
    RDS Multi-AZ + Read Replica + RDS Proxy
    3 issues solved: write blocking, 47/100 conn limit, untested backups since Nov 2022
    Accepted
  • ADR-0008
    Batch idempotency via S3 PutObject + upsert
    File-append bug discovered — retries now safe, no duplicate records on failure
    Accepted
Execution Plan

8 weeks. 3 parallel streams.

1

Weeks 1–2 — Foundations & Blockers

Resolve all 5 blockers: env vars, Secrets Manager, S3 buckets, Redis sessions, EventBridge decoupling. Docker Compose local environment validated.

2

Weeks 3–5 — Containerization (parallel)

Three independent streams: web app containerized → ECS; batch job migrated → AWS Batch; RDS provisioned with Multi-AZ + read replica.

3

Weeks 6–7 — Integration & Hardening

Cross-workload validation, security audit, backup restore drill, load testing on read replica isolation.

✓

Week 8–9 — Cutover

Blue/green deployment, DNS switchover, 48h parallel run, legacy decommission. First backup restore drill triggers tape decommission.
